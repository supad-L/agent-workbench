# M3 最小切片：API 角色执行单个开发任务 · 2026-11-09

用户于 2026-11-09 选择先走 API 路线，让工作台第一次真正“自己写代码”。本文是这一切片的执行依据。它按 DELIVERY 的 M3 拆分取最窄的一条纵向路径（M3-01 任务合同、M3-03 任务副本与差异、M3-05 工具代理、M3-07 证据采集的最小部分），**不**包含调度器、主 Agent 自动拆分派工、并行、正式审查、返工与集成（M3-02、M3-06、M4）。原方案文档的要求不变。

## 1. 用户可见行为

1. 项目页新增“任务”视图：列出本项目的开发任务及状态、执行角色、改动文件数。
2. “新建任务”：填写标题、任务说明，选择执行角色（必须已绑定 API 连接、已启用），指定允许修改的目录（例如 `src/pages/`）。可选：验证命令使用的本地镜像与容器运行时。
3. 点击“开始执行”：
   - 平台从项目管理区副本再复制出该任务的 **基线副本** 与 **工作副本**，原始项目和管理区副本都不会被修改。
   - 角色绑定的 API 模型通过平台工具读取文件、写入文件、在断网容器中运行命令；所有路径由平台校验。
4. 任务详情：运行状态、事件时间线、模型最终说明、改动文件列表与逐行差异、命令输出、用量入口；可取消、可显式继续（可能再次计费），可把改动导出为补丁文件。

## 2. 安全与数据边界

| 项目 | 规则 |
| --- | --- |
| 原项目 | 任何情况下不写入；任务只操作 `<数据目录>/tasks/<任务编号>/work` |
| 写入范围 | 只允许写入任务指定目录内的普通文件；`.git`、`.agent-workbench`、符号链接父目录、越界路径一律拒绝，拒绝原因作为工具结果返回模型 |
| 命令执行 | 仅当角色允许 `run_command` 且任务指定了本地镜像时提供；工作副本以只读方式挂载，`network=none`、只读根、UID 1000、移除 capabilities、私有 `/tmp`、单次 2 分钟、输出 64 KiB；不会在宿主机运行 |
| 模型凭证 | API Key 只在桌面主进程与本机后端之间传递，从不进入容器或工作副本 |
| 发送给模型的数据 | 任务说明、确认方案（如有）、模型通过工具读取的文件内容。创建任务时界面明确提示；任务不使用备用连接切换，避免把项目文件发给另一服务商 |
| 计费 | 沿用现有预约/结算账本；价格未知时不按零处理；重启后不自动重发请求 |
| 完成判定 | 模型停止调用工具即“执行结束”，**不等于验收通过或已集成**；改动只存在于任务工作副本 |

## 3. 实现要点

- **数据**：复用 `agent_runs`，新增 `kind = "task"` 与 `task` 字段（标题、说明、写入目录、可选镜像/运行时、结束时的改动清单）。不新增数据库表与迁移，旧版本数据不受影响。
- **Agent 循环**：`agent.Options` 增加可选上限（回合数、单轮输入、工具结果、输出 tokens）；试运行保持原有 4 回合 / 64 KiB 等限制不变，任务使用 30 回合 / 384 KiB / 48 KiB / 最多 8192 tokens，总时限 20 分钟。
- **工具**（角色工具与任务权限取交集）：`list_files`、`read_file`（角色需 `read_file`）；`write_file`（需 `write_file`）；`replace_in_file` 精确替换一处（需 `apply_patch` 或 `write_file`）；`run_command`（需 `run_command` 且任务有镜像）。可恢复的错误以文本返回模型，不中断运行。
- **差异**：结束后与基线副本比较，生成改动清单与统一格式差异（文本文件，单文件 ≤ 1 MiB，总量上限），二进制文件只标记变更；可导出 `.patch`。
- **接口**：`POST /api/projects/{id}/tasks`、`GET /api/projects/{id}/tasks/{run}/changes`；取消、继续、查询复用现有运行接口。桌面 IPC 新增 `tasks.start`、`tasks.changes`、`tasks.exportPatch`，同步加入预加载白名单。

## 4. 步骤与验收

| 步骤 | 内容 | 验收 |
| --- | --- | --- |
| T1 | 执行文档（本文） | — |
| T2 | 任务副本与差异（workspace） | 单元测试：复制排除 `.git`、写入越界拒绝、符号链接拒绝、差异正确 |
| T3 | Agent 循环可配置上限 | 原试运行测试不变通过；任务上限生效 |
| T4 | 任务运行：存储、工具代理、命令执行、HTTP 接口 | 合成模型端到端：读文件 → 写文件 → 越界被拒 → 结束后差异只含范围内文件；重启后不自动重发 |
| T5 | 桌面 IPC 与界面 | 界面测试：创建任务只提交连接引用、不提交凭证；差异展示；取消/继续 |

## 5. 明确不做（留给后续阶段）

主 Agent 拆分与派工、并发调度与目录冲突仲裁、正式审查与退回、自动合并回原项目或集成分支、命令联网与依赖安装、订阅账号（GPT/Claude）执行。

## 6. 实施记录（2026-11-09）

T1–T5 已实现，T6 中除“用户用真实 API 连接执行一次任务”外均已完成。

- **工作区**：`internal/workspace/task.go`（复制快照、跳过 `.git`、`TaskFiles` 经 `os.Root` 读写并校验写入范围、拒绝符号链接父目录）与 `unified.go`（Myers 行差异、git 兼容统一差异、二进制/过大文件标记、`CombinedPatch`）。
- **Agent 循环**：`agent.Limits` 可选上限；未设置时保持原 16 回合 / 64 KiB 输入 / 32 KiB 工具结果 / 4096 tokens / 32 KiB 调用参数。
- **存储**：`store.TaskSpec`、`TaskInput`、`NormalizeTask`、`CreateTaskRun`（只用主连接、需要读写工具、校验镜像 ID）、`RecordTaskChanges`；任务运行记录上限 4 MiB，试运行仍为 1 MiB。无数据库迁移。
- **运行服务**：`runservice.NewWithTasks`、`StartTask`（建立 `<数据目录>/tasks/<编号>/{base,work}`）、`TaskChanges`、工具代理（`list_files`、`read_file`、`write_file`、`replace_in_file`、`run_command`），20 分钟时限，结束时记录改动清单。
- **接口与桌面**：`GET/POST /api/projects/{id}/tasks`、`GET /api/projects/{id}/tasks/{run}/changes`；IPC `tasks.list/start/changes/exportPatch`（导出走系统保存对话框），预加载白名单同步。
- **界面**：项目页“任务”视图（任务列表、新建表单、详情：改动文件与逐行差异、模型说明、过程与工具记录、取消/继续/导出补丁）；角色试运行历史不再混入任务。
