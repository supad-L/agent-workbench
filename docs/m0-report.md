# M0 首批代码实施报告

日期：2026-10-22。阶段：M0 进行中，尚未整体通过。用户已确认方案并授权编码；本报告不把原型当作完整产品。

## 已完成的首批实现

- Go 项目、开发 CLI、版本固定的本地工具链和验证脚本。
- Messages、Chat Completions、Responses 的请求编码、流式响应、工具结果续接与取消。
- 连接地址规范化，完整端点、版本路径及本地测试地址校验。
- 十类 JSON Schema（原八类加代理元数据、账号网络绑定）、合成示例、OpenAPI 草案和跨合同 guard。
- 固定方案依据、审查成果/执行尝试匹配、发送者角色与执行代际检查。
- 跨连接别名的账号资源指纹；未实现实际凭证库或调度限额服务。
- 修改范围和冲突检查、完整源树清单、模式/链接/未跟踪文件差异、受基线保护的补丁。
- Docker / Podman 双运行时选择；只读源树与可写子目录参数编译、真实探针入口、清理与失败后置检查。保留 Docker 默认值，失败不静默换引擎。
- system 与 explicit_proxy 应用请求策略；enforced_proxy 明确拒绝未验证的强制隔离。
- 代理输入规范化与脱敏、规范账号绑定、不可变网络快照、认证修订检查、被引用代理删除 guard、可撤销 HTTP 会话与流取消；尚未接通持久服务和配置 UI。
- 需要显式连接配置的真实 API 工具回合探针；本轮仅以本地合成服务验证该命令。
- DeepSeek 官方 API 非思考方言、无密钥模板和交互终端隐藏输入脚本；两轮合成工具续接通过，真实 Key 尚未输入。

测试曾发现并修正：缺失用量被当作已知零、工具调用与结束原因不一致、Responses 完成文本丢失。进一步补充了取消后的清理、重复账号身份、陈旧审查、源目录挂载别名、符号链接及验收建议越权等场景。

Docker 生命周期测试使用明确标记的合成 driver，只证明编排、取消、清理与后置条件检查，不证明真实容器或网络隔离。没有通过假 driver 把 M0-05 标为通过。

## 尚未实现

完整 Web UI、项目数据持久化服务、用户确认鉴权、持久消息邮箱、实际主 Agent 调度、多 Agent 正式并行执行、审查返工状态机和串行集成都仍属于后续阶段。

当前 schema 与 guard 不能替代上述服务，也不能自动判断评审意见是否在语义上符合原方案。原始需求和验收没有因缺少环境而删减。
