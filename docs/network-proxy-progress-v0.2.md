# v0.2 网络原型实施记录

日期：2026-10-22。所属阶段：M0 / NET-01、NET-02 的合同与应用 HTTP 原型。未越过正式存储、权限及认证阶段门禁。

## 已完成

- 新增 `proxy_endpoint` 与 `network_binding` v1 Schema 和合成示例，合同总数增至十类。连接中的网络模式、DNS 与代理引用增加互斥检查；网络写接口只在 OpenAPI 草案中标为 planned、人类身份操作。
- `ParseProxy` 支持完整 URL 或拆分协议/主机/端口/认证；禁止混填、无协议/无明确端口、路径/查询/片段和控制字符。SOCKS5 归一成代理侧目标解析的 `socks5h`。
- 普通代理元数据仅含凭证引用；输入、瞬时凭证与含认证 URL 的 Policy 不经默认 JSON/fmt 输出敏感值。正式凭证库和编辑密码的“保持/替换/清除”仍未实现。
- 网络绑定由规范账号资源持有；解析时核对账号、代理存在/启用/身份及修订，得到不可变快照。绑定输入不能携带保护降级标志，保护要求从受信任 AccountPolicy 派生。公司 Messages 协议没有被自动认定为 Claude 订阅。
- 增加拒绝删除仍被引用代理的 guard；正式数据库完整引用检查待 NET-03。
- `AuthContext` 核对账号、认证实例和策略/代理修订，拒绝陈旧或错账号上下文；这是连续性校验原语，不是已实现的 OAuth 登录/回调服务。
- `Session` 为一个快照创建独立 HTTP transport；Close 会取消活动请求及流式响应、关闭空闲连接，并拒绝旧客户端继续发送请求。正式保存配置时停止旧执行者、改绑与重建的事务编排仍待 NET-03/05。
- 严格代理模式在读取代理凭证、开始认证或发出模型请求前返回未就绪；没有用普通 HTTP 代理伪装成浏览器/原生 CLI 网络隔离。

## 验证与实际边界

`python3 scripts/dev.py network` 或构建后的 `./bin/agent-workbench network-probe` 只启动本机回环目标和代理夹具，不读取账号、不访问公网、不调用模型、不更改系统网络。

| 场景 | 证据 |
| --- | --- |
| 本机模式与指定 HTTP 代理使用不同路径 | 本机回环 HTTP 实验通过 |
| 指定代理关闭后，目标直连计数不增加 | 本机回环反例通过 |
| NO_PROXY=*、环境 HTTP_PROXY 不能改变绑定 | 自动测试通过 |
| 两个独立快照并发发请求互不污染 | race detector 下自动测试通过 |
| 关闭会话中断已打开的流式响应并拒绝复用 | 实际回环请求自动测试通过 |
| 关闭一个账号会话后另一个仍可请求 | 本机回环实验与自动测试通过 |
| 缺失/停用代理、越权绑定、旧认证上下文 | guard 自动测试通过 |
| JSON/fmt/错误中无合成代理密码 | 正反例自动测试通过 |
| Claude 登录/续期/推理、DNS/IPv6/UDP/QUIC 旁路 | 未验证，严格模式仍 blocked |
| SOCKS5/HTTPS 真实代理供应商、住宅公网出口质量 | 未验证；当前仅验证格式/规范化与 HTTP 回环路由 |

CLI 报告明确使用 `loopback_http_not_network_isolation` 证据标签；不输出公网出口地址。

## 尚需接线的内容

账号别名的持久归并、唯一绑定与并发修改事务、代理凭证存储/更新、用户权限校验、健康检查存储、配置 UI、实际代理检测、保存配置到会话撤销的业务接线均属于后续 NET-03/04/05。不能将这里的底层原语当作完整代理管理服务。

本轮保留 Docker / Docker Desktop 与 Podman 双支持。Podman 的写边界探针已通过，仍不能证明 Claude 专用代理全链路已经就绪。

用户选择先验收 DeepSeek API。已核对官方接口并添加非思考模式测试模板、隐藏密钥输入脚本和两轮合成协议测试；真实验收需用户在本机输入 Key，见 [DeepSeek 本地接入测试](./DeepSeek-本地接入测试.md)。
