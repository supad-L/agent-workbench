# Agent Workbench 中文操作指南（M1）

本版提供项目、资料、手工需求记录、方案版本和自定义 API 配置。真实主 Agent 对话、派工、代码执行和审查返工属于后续阶段。

## 1. 打开工作台

在项目目录双击 **启动工作台.command**。它会打开已打包的 `output/desktop/mac-arm64/Agent Workbench.app`，并将工作台数据放在同目录下的 `data/desktop/`。本机项目位于 D 盘，因此这个入口的数据也在 D 盘。Electron 和 macOS 本身仍可能使用少量系统缓存，不能保证系统盘完全没有写入。

如果提示尚未打包，请按 [开发运行说明](./development.md) 构建。本地包没有 Apple 开发者签名和公证；系统若阻止打开，可在“系统设置 → 隐私与安全性”检查该应用的提示，不需要关闭系统安全功能。

直接双击 `.app` 时，默认使用 macOS 用户应用数据目录；需要保持数据在 D 盘时，使用上述启动入口。已经打开的同一实例会被切到前台；更改数据目录前先正常退出应用。

## 2. 新建或导入项目

1. 点击左侧 **新建 / 导入项目**，或首页 **创建第一个项目**。
2. 输入项目名称。从零开发时，目录留空即可。
3. 修改已有项目时，点击 **选择目录**，选择现有项目文件夹。
4. 点击 **创建项目**。左侧出现项目后点击它。
5. 切换到 **资料与快照**，检查管理区目录和导入清单。

导入会创建独立副本，包含未提交和未跟踪的源码。原目录之后的修改不会自动同步。`.git`、常见密钥文件、依赖和生成目录会被排除，符号链接不跟随；排除原因显示在清单中。排除规则不能识别所有自定义名称的秘密文件，导入前应检查自己的源码目录。

当前单次导入限制：最多 50,000 项、单文件 32 MiB、总内容 256 MiB；过大时会说明失败，不生成可用项目记录。

## 3. 记录需求和确认方案

1. 在 **需求与方案 → 需求记录** 输入需求，点击 **保存消息**。这一步只保存手工记录。
2. 点击 **编写草案**，填写方案标题、需求、工程约束和验收条目，每行一项。
3. 点击抽屉右上角 **保存草案**。检查内容；需要调整时点击 **编辑草案**。
4. 内容确认后，点击 **确认 V1**。页面显示 **当前确认 V1**，该版本被锁定。
5. 新需求请点击 **提出变更**，填写新内容及变更原因，保存为 V2 草案。
6. 未确认 V2 时，V1 继续生效。通过版本选择框可查看历史版本及内容哈希。

确认会校验刚查看的内容哈希、修订号和基线。若提示“数据已变化”，重新查看当前版本再处理；基于旧基线的草案需要重新基于当前确认方案提出变更。已确认版本不会被覆盖。

**验证权限边界** 按钮会尝试使用 Agent 身份确认方案，正常结果是请求被拒绝（403）。它不会连接真实模型或给 Agent 用户权限。

首次体验也可点击 **载入合成示例草案**。示例仅用于演示，确认前应改成自己的需求。

## 4. 导入需求文档

1. 打开项目的 **资料与快照**。
2. 点击 **导入 Markdown / 文本 / PDF**，选择文件。
3. 点击该资料的 **查看内容**。同名资料再次导入会保留为新的资料版本。

Markdown、UTF-8 文本和带可提取文本的 PDF 会保存原文件副本、来源和哈希。单份文件最多 8 MiB，PDF 最多解析 128 页，提取文本最多 2 MiB。扫描 PDF、复杂 PDF 或不可读文本会显示“需要额外解析”，本版没有 OCR。导入资料不会自动修改已确认方案。

## 5. 配置 DeepSeek、公司中转或其他 API

1. 点击左侧 **模型连接 → 新增连接**。
2. 填写便于识别的连接名称。
3. 在 **接口协议** 中选择服务实际支持的 `Messages`、`Chat Completions` 或 `Responses`。Claude Code 兼容中转通常选择 Messages，最终以中转提供的接口为准。
4. 选择地址类型。**Base URL** 会补齐接口路径，支持根地址、`/v1` 或公司前缀；**完整端点** 按输入的路径请求。
5. 填写服务地址、模型 ID、认证方式和 API Key。模型 ID 以服务商提供的名称为准。
6. 选择网络方式。**跟随本机网络** 沿用本机路由、VPN/TUN 和分流；**使用指定出口代理** 需输入含协议和端口的代理 URL，可包含代理认证。
7. 如服务有特殊认证，在 **更多设置** 中添加额外请求头。DeepSeek 的 Chat Completions 可选择 DeepSeek 兼容选项。
8. 点击 **检查配置**，核对显示的实际端点。这一步不请求模型。
9. 点击 **保存连接**。密钥使用 Electron 的系统加密能力保存在本地加密文件，保存后不回显；编辑时留空保留已有密钥。若系统加密不可用则拒绝保存。
10. 需要实际验收时点击 **测试连接**，会发送两轮模型请求以验证工具调用及结果回传，消耗 API 额度。

本机 Clash 的系统代理与 TUN 都打开时，“跟随本机网络”使用当前本机路由；纯系统 HTTP 代理开关未必被 Go 请求自动采用。仅开系统代理而没有 TUN 时，建议显式配置本地代理地址。公司域名可沿用本机 DNS，但最终连通性仍需在公司网络实际测试。

指定代理是 API 请求级代理，故障时不会回退直连。它尚不等于 Claude 浏览器登录、CLI、续期、DNS/IPv6 全链路的强制出口隔离。本版未提供 GPT/Claude 订阅登录入口；不要用连接测试替代其后续专门验收。

## 6. 查看记录、退出与备份

**事件记录** 展示项目的持久事件，重开项目或断线后按游标恢复，界面保留最近 100 条；后台历史仍在数据库中。正常退出后再次打开，可继续查看项目、需求、资料和方案。

需要备份时先退出工作台，再备份整个 `data/desktop/`。`state/` 内含 SQLite 和项目/资料副本，`connections.enc` 为加密连接配置。连接加密依赖当前系统账号，换机或换系统用户不能保证解密；迁移后必要时重新填写密钥。不要把该目录提交到 Git。
