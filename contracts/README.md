# M0 接口合同

当前 M1 服务已实现项目、方案、资料、消息与事件等基础接口，实际请求和权限见 [M1 本地接口说明](../docs/m1-api.md)。本目录 OpenAPI 保留完整规划草案，不能把其中 planned 路由视为已实现；JSON Schema v1 继续用于内容校验。

本目录的 JSON Schema 使用 draft 2020-12，版本为 1。scripts/generate-contracts.py 是定义来源，运行后生成 schema 与合成示例；修改定义后必须重新生成并评审差异。

| 合同 | 定义 |
| --- | --- |
| plan | 已确认方案的内容；确认回执另由用户权限服务持有 |
| task | 任务基线、环境、范围、依据、验证与轮数 |
| connection | 接口、认证引用、账号资源和网络策略，不包含真实密钥 |
| review | 正式问题与不阻塞交付的建议 |
| verification | 固定验证环境、入口、测试包与摘要 |
| message | 双向通信消息、当前执行身份、幂等键和分类载荷 |
| account_resource | 跨连接账号资源、刷新所有者与额度识别状态 |
| runtime_event | 运行进度；不授予任务完成或验收权限 |
| proxy_endpoint | 代理地址、凭证引用、启用状态与修订；不保存用户名/密码或认证 URL |
| network_binding | 规范账号资源上的本机/指定代理二选一与策略修订；不允许前端提交保护降级标志 |

contracts.Validator 在不允许外部 schema 加载的情况下编译并验证这些文件。internal/contractguard 进一步检查跨合同引用、成果匹配、消息身份和角色。

Schema 校验不代表用户已经授权；通过编号检查也不能证明一条评审意见在语义上正确。正式确认、持久化邮箱、投递回执与调度由后续业务服务实现。本次没有用内存模拟器冒充持久化通信中枢。

网络绑定按账号资源持有。连接合同中的 egress 是兼容原型配置；正式服务必须用账号绑定解析有效策略，不能允许连接别名各自覆盖同一受保护账号。internal/egress 已提供格式校验、账号匹配、不可变快照及可撤销 HTTP 会话原语；持久化、并发修改事务、角色权限、代理凭证编辑语义和正式 HTTP 接口仍待 M1/M2。
